# Infrastructure Setup

All Azure resources are created with a single Bicep deployment. You do not need to create
anything manually in the portal — the template handles Resource Group, UAMI, Key Vaults,
Container Registry, Container App Environment, and Automation Account.

<Callout type="info">
  **You do not need Docker installed.** Container images are built directly in Azure using
  `az acr build` — no local Docker daemon required.
</Callout>

---

## What gets created automatically

| Resource | What it does |
|----------|-------------|
| **Resource Group** | Container for all project resources |
| **User-Assigned Managed Identity (UAMI)** | The system's identity — authenticates to Graph API, Key Vault, ACR with no passwords |
| **Key Vault — config** | Stores Jira, Teams, SharePoint, and OpenAI credentials |
| **Key Vault — rotation** | Stores newly generated secret values after rotation |
| **Azure Container Registry** | Stores the Docker images for Container 1 and Container 2 |
| **Container App Environment** | The runtime environment for both containers |
| **Azure Automation Account** | Runs the weekly monitoring and rotation runbooks |
| **Log Analytics Workspace** | Captures all container and runbook logs |

All RBAC role assignments are wired up automatically — no manual permission setup needed.

|---------|--------------|
| **Azure subscription** | Contributor or Owner role |
| **Azure OpenAI** | Quota approval required — request via Azure portal if not already approved |
| **Microsoft 365 / SharePoint** | Admin access to create a SharePoint team site |
| **Microsoft Teams** | Ability to add connectors to a Teams channel |

## Step-by-step deployment

<Steps>

### Get your Azure Object ID

You need your personal Object ID to grant yourself Key Vault access during deployment:

```bash
# This prints your user Object ID — copy the GUID it returns
az ad signed-in-user show --query id -o tsv

# Example output:
# a1b2c3d4-e5f6-7890-abcd-ef1234567890
```

### Fill in foundation.parameters.json

Open `secret-governance-infra/infra/foundation.parameters.json` and update these four values:

```json
{
  "parameters": {
    "location": {
      // Azure region — pick the one closest to your users
      // Options: eastasia, eastus, westeurope, southindia, australiaeast
      "value": "eastasia"
    },
    "resourceGroupName": {
      // Name for your new resource group
      // Convention: use your company name + -secret-governance-rg
      "value": "contoso-secret-governance-rg"
    },
    "prefix": {
      // Short prefix used to name ALL resources — 3-8 lowercase letters, no spaces
      // Example: "secgov" creates secgov-uami, secgovacr, secgov-kv-config, etc.
      "value": "secgov"
    },
    "adminObjectId": {
      // Your Object ID from the command above
      "value": "a1b2c3d4-e5f6-7890-abcd-ef1234567890"
    }
  }
}
```

<Callout type="warning">
  The prefix is used to name all resources. Choose something short and meaningful.
  Once deployed, resource names cannot be changed without redeploying everything.
</Callout>

### Run the foundation deployment

```bash
cd secret-governance-infra/infra

# This single command creates ALL Azure resources
# Takes 3-5 minutes to complete
az deployment sub create \
  --location eastasia \
  --template-file foundation.bicep \
  --parameters '@foundation.parameters.json'
```

When complete, it prints output values like this:

```
uamiResourceId      = /subscriptions/.../secgov-uami
uamiClientId        = 17c0380e-395b-4b6b-bebb-bfd1dc439530
configKeyVaultUrl   = https://secgov-kv-config.vault.azure.net/
rotationKeyVaultUrl = https://secgov-kv-rotation.vault.azure.net/
acrLoginServer      = secgovacr.azurecr.io
containerAppEnvName = secgov-cae
```

<Callout type="warning">
  **Save these output values** — you will need them when populating Key Vault secrets
  and deploying the Container App.
</Callout>

### Grant UAMI Microsoft Graph permissions

The UAMI needs two Graph API permissions to read App Registrations and write secrets:

```bash
# Store the UAMI's service principal ID
SP_ID=$(az ad sp list \
  --filter "appId eq '<UAMI_CLIENT_ID_FROM_ABOVE>'" \
  --query "[0].id" -o tsv)

# Store the Microsoft Graph service principal ID
GRAPH_SP=$(az ad sp list \
  --filter "appId eq '00000003-0000-0000-c000-000000000000'" \
  --query "[0].id" -o tsv)

# Get the exact role ID for Application.ReadWrite.All in YOUR tenant
# (role IDs can vary slightly between tenants)
az rest \
  --method GET \
  --uri "https://graph.microsoft.com/v1.0/servicePrincipals/$GRAPH_SP/appRoles" \
  --query "value[?value=='Application.ReadWrite.All'].{Name:value, ID:id}" \
  -o table
```

Then grant the permission using the role ID from the output above:

```bash
# Create the JSON body and save to a temp file (avoids shell escaping issues)
cat > /tmp/role-assignment.json << EOF
{
  "principalId": "$SP_ID",
  "resourceId": "$GRAPH_SP",
  "appRoleId": "<ROLE_ID_FROM_ABOVE>"
}
EOF

az rest \
  --method POST \
  --uri "https://graph.microsoft.com/v1.0/servicePrincipals/$SP_ID/appRoleAssignments" \
  --headers "Content-Type=application/json" \
  --body "@/tmp/role-assignment.json"
```

Repeat for `Application.Read.All` and `Sites.Selected`.

### Grant UAMI SharePoint site access (Sites.Selected)

`Sites.Selected` restricts the UAMI to only your specific SharePoint site — not all sites
in the tenant. This must be granted via Graph Explorer since there is no Azure CLI command for it.

1. Go to [Graph Explorer](https://developer.microsoft.com/graph/graph-explorer)
2. Sign in with your admin account
3. Run this POST:

```
POST https://graph.microsoft.com/v1.0/sites/<YOUR_SITE_ID>/permissions
```

```json
{
  "roles": ["write"],
  "grantedToIdentities": [{
    "application": {
      "id": "<UAMI_CLIENT_ID>",
      "displayName": "secret-governance-uami"
    }
  }]
}
```

<Callout type="info">
  Use only the **site collection ID** (first GUID after the hostname) in the URL — not the
  full composite site ID with both GUIDs. Graph Explorer handles the rest.
</Callout>

### Populate Key Vault secrets

Fill in `keyvault-secrets.parameters.json` with your service credentials, then run:

```bash
# This populates ALL Key Vault secrets in one command
az deployment group create \
  --resource-group <YOUR_RG> \
  --template-file keyvault-secrets.bicep \
  --parameters '@keyvault-secrets.parameters.json'
```

### Build and deploy the Container App

```bash
ACR="<YOUR_ACR_LOGIN_SERVER>"   # e.g. secgovacr.azurecr.io
RG="<YOUR_RESOURCE_GROUP>"

# Build Container 2 first (Monitor API)
az acr build \
  --registry $ACR \
  --resource-group $RG \
  --image secret-governance/monitor-mcp:latest \
  ./container-2

# Build Container 1 (LangChain Agent)
az acr build \
  --registry $ACR \
  --resource-group $RG \
  --image secret-governance/langchain-agent:latest \
  ./container-1

# Deploy both containers to Container App
az deployment group create \
  --resource-group $RG \
  --template-file deploy.bicep \
  --parameters '@deploy.parameters.json'
```

</Steps>

## UAMI permissions reference

The UAMI is the system's identity — it authenticates to everything using managed identity,
so there are no client secrets to manage or rotate.

| Permission | Type | Purpose |
|-----------|------|---------|
| `Application.Read.All` | Application | Read all App Registrations and their secret expiry dates |
| `Application.ReadWrite.All` | Application | Create new secrets during rotation |
| `Sites.Selected` | Application | Read/write the SecretAlertRegistry SharePoint list only |
| `Key Vault Secrets User` | RBAC role | Read config secrets from Key Vault |
| `Key Vault Secrets Officer` | RBAC role | Write new secret values to rotation Key Vault |
| `AcrPull` | RBAC role | Pull container images from Azure Container Registry |

<Callout type="warning">
  **Do not grant `Directory.Read.All` or `Sites.ReadWrite.All`.** These are broader than needed.
  The system uses `Sites.Selected` which limits SharePoint access to only your specific site.
</Callout>
