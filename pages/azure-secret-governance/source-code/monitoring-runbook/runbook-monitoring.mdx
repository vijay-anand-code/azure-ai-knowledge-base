# runbook_monitoring.py

**Location:** `devsecops-secret-governance-runbooks/devsecops-secret-governance-monitor-langchain.py`
(the file on disk is named `devsecops-secret-governance-monitor-langchain.py`; this page keeps
the `runbook_monitoring.py` slug used elsewhere in these docs for continuity)

**Runtime:** Python 3.10, Azure Automation Account

**Schedule:** Weekly at `00:30`, 30 minutes after discovery. The gap gives discovery time to
finish writing to `SecretAlertRegistry` before monitoring reads that same list, so monitoring
never reads a half-written run.

**What it does:** Sends a POST to whatever `AGENT_ENDPOINT` points at, with an instruction to run
the weekly monitoring check, and returns as soon as the request is accepted. It is a thin trigger
stub: it contains none of the actual classification/ticket/alert logic itself, only the request
and a success/failure check.

<Callout type="warning">
  `AGENT_ENDPOINT` targets **Container 1's `/run` endpoint** (the LangChain agent), not Container
  2 directly. The script's own docstring says its purpose is to "trigger the Secret Monitoring
  governance cycle in devsecopssecretgovernancelangchainagent", i.e. the LangChain agent
  container, and `/run` is only exposed by Container 1 (Container 2 exposes
  `/tools/run_secret_monitoring`, not `/run`). Container 1's `/run` handler
  (`run_governance_cycle()` in `main.py`) hands the instruction to the LangChain agent, which
  normally responds by calling its `run_secret_monitoring` tool: that tool is what actually
  forwards the request internally to Container 2's `/tools/run_secret_monitoring` via Container
  1's `_call_monitor()` helper. So the real path is: this runbook → Container 1 `/run` → LangChain
  agent → Container 2 `/tools/run_secret_monitoring`, not a direct hit on Container 2. An earlier
  version of this page described `AGENT_ENDPOINT` as pointed straight at Container 2, bypassing
  Container 1 entirely; that was incorrect and has been corrected here.
</Callout>

## Key design decisions

| Decision | Reason |
|----------|--------|
| Fire-and-forget pattern | Container 1's `/run` returns immediately and runs the actual cycle as a background task. A 30s timeout avoids the runbook hanging if the container is slow to respond |
| Timeout treated as success | If no response arrives within 30s, or the connection resets, the request was already accepted and the cycle is running. Only a genuine HTTP error status from the container counts as a real failure. Raising an error on a plain timeout would be a false failure |
| Minimal runbook | All classification, ticket, and alert logic lives in Container 2's `decision_engine.py`. This runbook only fires the trigger: the request passes through Container 1's LangChain agent on the way there, but there's no reasoning step involved for a fixed weekly instruction, so the agent effectively just calls its one `run_secret_monitoring` tool and returns |

## Required configuration

**Automation Variables** (set in Azure Automation Account):

| Variable | Value |
|----------|-------|
| `AGENT_ENDPOINT` | Container 1's `/run` URL, e.g. `https://<container-app-fqdn>/run` |
| `AGENT_API_KEY` | Shared secret header value (set to empty string `""` to disable the header entirely) |

```python
"""
devsecops-secret-governance-monitor-langchain.py - Azure Automation Runbook
==============================================================================
Purpose : Trigger the Secret Monitoring governance cycle in devsecopssecretgovernancelangchainagent
Schedule: Every 7 days (configured in Azure Automation Account)
Runtime : Python 3.10 (Azure Automation)

The /run endpoint now returns immediately (background task).
This runbook just fires the request and confirms it was received.
If the container takes longer than 30s to acknowledge, we treat it
as accepted and move on - the agent continues running in background.

Required Automation Variables:
  AGENT_ENDPOINT   - e.g. https://<container-app-fqdn>/run
  AGENT_API_KEY    - shared secret header value (set to "" to disable)
"""

import automationassets
import urllib.request
import urllib.error
import json
import sys
from datetime import datetime, timezone

# ── Config from Automation Variables ─────────────────────────────────────────

def _get_var(name: str) -> str:
    value = automationassets.get_automation_variable(name)
    if not value:
        raise ValueError(f"Automation Variable '{name}' is not set or is empty.")
    return str(value).strip()

AGENT_ENDPOINT = _get_var("AGENT_ENDPOINT")
AGENT_API_KEY  = _get_var("AGENT_API_KEY")

# ── Request ───────────────────────────────────────────────────────────────────

def trigger_monitoring() -> dict:
    payload = json.dumps({
        "instruction": (
            "Run the weekly secret monitoring check. "
            "Summarise everything: secrets scanned, new Jira tickets raised, "
            "Teams alerts sent, SharePoint rows created or updated, and any errors."
        )
    }).encode("utf-8")

    headers = {"Content-Type": "application/json"}
    if AGENT_API_KEY:
        headers["X-API-Key"] = AGENT_API_KEY

    req = urllib.request.Request(
        AGENT_ENDPOINT,
        data=payload,
        headers=headers,
        method="POST",
    )

    try:
        with urllib.request.urlopen(req, timeout=30) as response:
            body = response.read().decode("utf-8")
            return json.loads(body)

    except urllib.error.HTTPError as e:
        error_body = e.read().decode("utf-8")
        raise RuntimeError(f"Agent returned HTTP {e.code}: {error_body[:500]}") from e

    except Exception:
        # Timeout or connection reset - agent accepted and is running in background
        print("[INFO] No immediate response - agent is running in background.")
        return {
            "success": True,
            "message": "Cycle triggered - agent running in background",
            "startedAt": datetime.now(timezone.utc).isoformat()
        }

# ── Main ──────────────────────────────────────────────────────────────────────

def main():
    started = datetime.now(timezone.utc).isoformat()
    print(f"[{started}] Monitoring Runbook started.")
    print(f"  Target: {AGENT_ENDPOINT}")

    try:
        result = trigger_monitoring()
    except Exception as exc:
        print(f"ERROR: {exc}")
        sys.exit(1)

    if result.get("success"):
        print(f"[OK] Monitoring cycle triggered successfully.")
        print(f"  Started at : {result.get('startedAt', 'N/A')}")
        print(f"  Message    : {result.get('message', '')}")
        print(f"  Summary    : {result.get('summary', 'Agent running in background - check container logs')}")
    else:
        print(f"[FAILED] Agent reported failure:")
        print(f"  Error: {result.get('error', 'unknown')}")
        sys.exit(1)

main()
```
