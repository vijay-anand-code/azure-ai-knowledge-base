# Source Code

Complete source for every file in the secret governance system: runbooks that run in
Azure Automation and the container files that power the monitoring API.

---

## Runbooks

| File | Schedule | What it does |
|------|----------|-------------|
| [runbook_discovery.py](/azure-secret-governance/source-code/discovery-runbook/runbook-discovery) | Mon 00:00 | Scans all App Registrations, fetches owners in parallel, batch-writes to SharePoint |
| [owner_sync_local.py](/azure-secret-governance/source-code/owner-sync-runbook/owner-sync-local) | Manual | Run locally from a laptop, adds `DevSecOpsOwnership` identities as Entra owners |
| [runbook_monitoring.py](/azure-secret-governance/source-code/monitoring-runbook/runbook-monitoring) | Mon 00:30 | Triggers the monitoring container, fire and forget |
| [runbook_rotation.py](/azure-secret-governance/source-code/rotation-runbook/runbook-rotation) | Mon 01:00 | Rotates P1/P2/P3 secrets, stores in Key Vault, updates Jira and SharePoint |

## Jira Automation Rules

Raw rule exports from the KAN project, kept as a ground-truth reference alongside the
[Jira Automation](/azure-secret-governance/jira) page's prose walkthrough.

| Rule | Trigger | What it does |
|------|---------|-------------|
| [Sync field edits after In Progress](/azure-secret-governance/source-code/jira-automation-rules/sync-field-edits-after-in-progress) | Any edit to 9 named custom fields | Locks fields while Resolved; overwrite-syncs to SharePoint otherwise |
| [Sync ticket status to SharePoint](/azure-secret-governance/source-code/jira-automation-rules/sync-ticket-status-to-sharepoint) | Transition to Resolved/In Progress/To Do/Waiting for Customer | The main status-transition sync, with a Teams failure alert |
| [Validate intake fields on In Progress](/azure-secret-governance/source-code/jira-automation-rules/validate-intake-fields-on-in-progress) | Transition to In Progress or Resolved | Bounces the ticket back to To Do if required fields are missing/invalid |
