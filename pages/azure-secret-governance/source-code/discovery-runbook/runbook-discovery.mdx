# runbook_discovery.py

**Location:** `secret-governance-infra/runbooks/runbook_discovery.py`

**Runtime:** Python 3.10 — Azure Automation Account

**Schedule:** Weekly at `00:00`, 30 minutes before monitoring. Also run manually when new App Registrations are added.

**What it does:** Fetches all App Registrations and their secrets from Entra ID, resolves owners in parallel using a thread pool, classifies each secret into a severity bucket, and batch-writes rows to the `SecretAlertRegistry` SharePoint list using Graph `$batch`.

---

## Key design decisions

| Decision | Reason |
|----------|--------|
| `ThreadPoolExecutor` for owner fetching | Azure Automation is synchronous Python — asyncio is not available. Threads drop owner-fetch time from ~4 min to under 1s for 255 apps |
| Graph `$batch` for SharePoint writes | Bundles up to 20 POST/PATCH requests into a single HTTP call — avoids throttling on large tenants |
| Never overwrites `AlertStatus` | Only monitoring changes `AlertStatus`. Discovery only stamps owners, severity, and expiry — safe to run anytime |
| P1 through P4 and ExpiredManualReview all written to SecretAlertRegistry | Owners are stamped on every bucket, including P4 (61+ days, safe), so they're already in place when a secret ages down into P3, P2, and beyond. Only the "Ignore" bucket (expired 8+ days) is excluded from this list |
| Ignore bucket routed to IgnoredSecretRegistry, not skipped | Secrets expired 8+ days ago have no remediation value in the active list, but are still upserted into IgnoredSecretRegistry (with owners and an IgnoreReason) rather than dropped entirely |
| `ManualAppOwners`, `TeamName`, `ProductName`, `ProductTeamkeyVaultName` never written by discovery | All four are excluded from both the new-row fields and the existing-row diff/PATCH logic, on every run. `ManualAppOwners` is filled in by a human (or resolved by monitoring/owner sync from `ProductName`); the other three are filled in by hand once per app, or copied automatically onto a rotated secret's new row by monitoring's lineage tracking, never by discovery |
| Backup: write new snapshot before purging the old one | Each run's backup of SecretAlertRegistry and IgnoredSecretRegistry is written first; only after that succeeds are the prior run's backup rows purged, so there's never a moment with zero backup for either list |
| Ignored-to-active recovery | A secret sitting in IgnoredSecretRegistry whose `endDateTime` is later renewed in Entra gets a fresh SecretAlertRegistry row created and its stale Ignored row deleted |
| Two credential scopes, not one | Entra scanning and SharePoint access are deliberately kept on separate federated credentials. See "Multi-tenant credentials" below |
| `TenantID` stamped per scanned tenant | Each row's `TenantID` reflects the tenant the app was actually fetched from, not a static home-tenant default. (The `TenantName` column was removed from SharePoint entirely, discovery no longer writes it anywhere) |
| Reconciliation totals in the run summary | End of run, discovery prints total apps scanned and total secrets seen in Graph, meant to be diffed directly against a manual Entra CLI count |
| 404 PATCH → retry as POST | If a SharePoint item was deleted externally, discovery creates a fresh row instead of failing |
| Federated credential | UAMI asserts identity to App Registration — no client secrets or certificates needed |

---

## Multi-tenant credentials

Discovery scans App Registrations across multiple Entra ID tenants, but SharePoint itself only ever lives in one tenant. Those two facts need two separate credential scopes:

| Credential | Tenant scope | Used for |
|---|---|---|
| Per-tenant scanning credential | One federated credential is built for every entry in `CROSS-TENANT-TENANT-IDS` (plural, comma-separated). Falls back to the older singular `CROSS-TENANT-TENANT-ID` if the plural secret isn't set | Fetching App Registrations and their owners |
| Home-tenant SharePoint credential | Always `HOME-TENANT-ID`, falling back to `GRAPH-TENANT-ID` if not set | Reading and writing SecretAlertRegistry, IgnoredSecretRegistry, and both backup lists |

Both credentials assert through the same UAMI and the same `CROSS-TENANT-APP-ID` App Registration, the split is about which tenant each credential is scoped to, not a second App Registration.

<Callout type="warning">
  An earlier version of this runbook used a single credential, scoped to whatever tenant was
  currently being scanned, for both Entra and SharePoint calls. That worked only by coincidence
  when the scanned tenant and the SharePoint tenant were the same. Once `CROSS-TENANT-TENANT-IDS`
  started pointing at a genuinely different tenant for multi-tenant scanning, every SharePoint
  call inherited that same tenant scope too, producing
  `{"code":"BadRequest","message":"Tenant does not have a SPO license."}`. The fix keeps one
  federated credential per scanned tenant for Entra calls, and a separate credential permanently
  pinned to the home tenant for every SharePoint call.
</Callout>

  `Sites.Selected` permissions granted with admin consent in every tenant listed in
  `CROSS-TENANT-TENANT-IDS`.
</Callout>

def _http(method: str, url: str, headers: dict,
          body: dict | None = None, timeout: int = 30) -> dict:
    """Single HTTP call — no retry. Use _http_with_retry for SP writes."""
    data = json.dumps(body).encode("utf-8") if body else None
    req  = urllib.request.Request(url, data=data, headers=headers, method=method)
    try:
        with urllib.request.urlopen(req, timeout=timeout) as resp:
            raw = resp.read().decode("utf-8")
            return json.loads(raw) if raw else {}
    except urllib.error.HTTPError as e:
        body_text = e.read().decode("utf-8")[:300]
        raise RuntimeError(f"HTTP {e.code} {method} {url}: {body_text}") from e

def _http_with_retry(method: str, url: str, headers: dict,
                     body: dict | None = None, timeout: int = 30) -> dict:
    """HTTP call with exponential-backoff retry for transient failures."""
    last_exc: Exception | None = None
    for attempt in range(1, RETRY_MAX + 1):
        try:
            return _http(method, url, headers, body, timeout)
        except (RuntimeError, urllib.error.URLError, OSError) as exc:
            last_exc = exc
            if attempt < RETRY_MAX:
                wait = RETRY_BACKOFF * (2 ** (attempt - 1))
                log.warning("Attempt %d/%d failed (%s) — retrying in %.1fs",
                            attempt, RETRY_MAX, exc, wait)
                time.sleep(wait)
    raise RuntimeError(f"All {RETRY_MAX} attempts failed: {last_exc}") from last_exc

def _get(url: str, hdrs: dict, timeout: int = 30) -> dict:
    return _http("GET", url, hdrs, timeout=timeout)

def _post_retry(url: str, hdrs: dict, body: dict, timeout: int = 30) -> dict:
    return _http_with_retry("POST", url, {**hdrs, "Content-Type": "application/json"}, body, timeout)

def _patch_retry(url: str, hdrs: dict, body: dict, timeout: int = 30) -> dict:
    return _http_with_retry("PATCH", url, {**hdrs, "Content-Type": "application/json"}, body, timeout)

# BUCKET CLASSIFICATION — mirrors decision_engine.py exactly
# ─────────────────────────────────────────────────────────────────────────────

def _classify_bucket(days: int) -> str:
    """
    Classify a secret into an expiry bucket based on days remaining.
    All buckets are classified and written to SecretAlertRegistry, except
    Ignore (8+ days expired), which goes to IgnoredSecretRegistry instead.

    CORRECTED — matches decision_engine.py's classify_bucket() exactly,
    after the renumbering that merged the old P1 (0-3) and P2 (4-7) into a
    single P1 (0-7), and shifted every bucket below it down by one. Whether
    a P1 secret specifically tags someone (0-3 days) or sends a plain Teams
    alert (4-7 days) is a decision made in decision_engine.py's
    should_tag_p1(), not something discovery needs to know about — discovery
    only classifies the bucket, it does not send alerts or tickets.

    P1  0-7 days   CRITICAL     (0-3 days additionally tags someone, in
                                  monitoring — discovery does not distinguish
                                  this, it only classifies)
    P2  8-30 days  WARNING
    P3  31-60 days INFORMATION
    P4  61+ days   SAFE
    """
    if days > 60:    return "P4"                  # safe — 61+ days
    if days >= 31:   return "P3"                  # info — 31-60 days
    if days >= 8:    return "P2"                  # warning — 8-30 days
    if days >= 0:    return "P1"                  # critical — 0-7 days
    if days >= -7:   return "ExpiredManualReview" # expired 1-7 days ago
    return "Ignore"                               # expired 8+ days ago

def _expiry_notice(days: int, bucket: str) -> str:
    """Human-readable expiry notice for SharePoint ExpiryNotice column."""
    if bucket == "Ignore":
        return f"Expired {abs(days)} days ago — ignored"
    if bucket == "ExpiredManualReview":
        return f"EXPIRED {abs(days)} days ago — manual review required"
    if days == 0:
        return "Secret expires TODAY"
    if days < 0:
        return f"Secret EXPIRED {abs(days)} days ago"
    return f"Secret Expiring in {days} days"

def _parse_graph_datetime(expiry_str: str) -> datetime:
    """
    Parses Graph API's endDateTime, normalizing fractional seconds first.

    WHY THIS EXISTS: Python 3.10's datetime.fromisoformat() only accepts
    fractional seconds with exactly 0, 3, or 6 digits. Graph API returns
    arbitrary precision (we've observed both 5-digit and 7-digit fractional
    seconds in production, e.g. "...11.74517Z" and "...37.8905613Z") —
    Python 3.10 raises ValueError on these, which was silently caught
    upstream and misclassified secrets as far-future (safe) instead of
    their true expired state. This is fixed natively in Python 3.11+
    (fromisoformat became far more lenient), but this runbook targets 3.10
    in Azure Automation, so we normalize manually here instead of relying
    on a runtime upgrade.

    Truncates fractional seconds to 6 digits (microseconds) if longer,
    pads with trailing zeros if shorter — either way produces a valid
    6-digit fractional value that fromisoformat() accepts on 3.10.
    Sub-microsecond precision is irrelevant for day-level expiry math.
    """
    match = re.search(r'\.(\d+)', expiry_str)
    if match:
        frac = match.group(1)[:6].ljust(6, '0')
        expiry_str = expiry_str[:match.start()] + '.' + frac + expiry_str[match.end():]
    return datetime.fromisoformat(expiry_str.replace("Z", "+00:00"))

# US Eastern time — auto-handles EST/EDT daylight saving transitions.
# All timestamps written to SharePoint (LastChecked, ExpirationDate,
# BackupRunDate, LoggedDate, etc.) are displayed in this timezone.
_EASTERN_TZ = ZoneInfo("America/New_York")

def _format_datetime_est(dt: datetime) -> str:
    """
    Formats a datetime (assumed timezone-aware, or naive-UTC if not) as a
    12-hour clock string in US Eastern time, with AM/PM — no ISO 8601
    letters (no 'T', no 'Z'). Example: "2026-07-22 07:50:53 AM".

    zoneinfo's America/New_York automatically applies EST (UTC-5) or EDT
    (UTC-4) depending on the date — no manual DST handling needed.
    """
    if dt.tzinfo is None:
        dt = dt.replace(tzinfo=timezone.utc)
    eastern_dt = dt.astimezone(_EASTERN_TZ)
    return eastern_dt.strftime("%Y-%m-%d %I:%M:%S %p")

def _now_est_string() -> str:
    """Current moment, formatted per _format_datetime_est — used for
    LastChecked, BackupRunDate, LoggedDate, and other 'as of now' fields."""
    return _format_datetime_est(datetime.now(timezone.utc))

# STEP 1 — Fetch ALL App Registrations from Entra ID
# ─────────────────────────────────────────────────────────────────────────────

def fetch_all_applications_for_tenant(tenant_id: str) -> list[dict]:
    """
    Fetches ALL App Registrations from a SPECIFIC tenant's Entra ID,
    including all secrets. No filtering — discovery classifies every
    secret; the Ignore bucket is routed to a separate list rather than
    dropped.
    """
    url = (
        "https://graph.microsoft.com/v1.0/applications"
        "?$select=id,appId,displayName,passwordCredentials"
        "&$top=999"
    )

    apps: list[dict] = []
    hdrs = _auth_hdrs_for_tenant(tenant_id)
    while url:
        b = _get(url, hdrs, timeout=30)
        apps.extend(b.get("value", []))
        url = b.get("@odata.nextLink")

    log.info("Fetched %d App Registrations from tenant %s", len(apps), tenant_id)
    return apps

def fetch_all_applications_all_tenants() -> list[dict]:
    """
    Loops through every tenant in CROSS_TENANT_TENANT_IDS, fetching all App
    Registrations from each. Each app dict gets a '_sourceTenantId' key
    added so downstream code (owner fetching, which also needs the correct
    per-tenant token) knows which tenant it came from.

    A failure fetching ONE tenant does not abort the whole run — it's
    logged and that tenant contributes zero apps, but other tenants still
    get scanned. This matters for multi-tenant reliability: a temporary
    issue with one client's tenant (revoked consent, expired trust, etc.)
    shouldn't block discovery for every other tenant.
    """
    all_apps: list[dict] = []
    tenant_errors: list[str] = []

    for tenant_id in CROSS_TENANT_TENANT_IDS:
        try:
            apps = fetch_all_applications_for_tenant(tenant_id)
            for app in apps:
                app["_sourceTenantId"] = tenant_id
            all_apps.extend(apps)
        except Exception as e:
            tenant_errors.append(f"Tenant {tenant_id}: fetch_all_applications failed: {e}")
            log.error("Failed to fetch applications from tenant %s: %s", tenant_id, e)

    log.info("Fetched %d total App Registrations across %d tenant(s)",
             len(all_apps), len(CROSS_TENANT_TENANT_IDS))
    return all_apps, tenant_errors

# ─────────────────────────────────────────────────────────────────────────────
# STEP 2 — Fetch owners for one App Registration (called in parallel)
# ─────────────────────────────────────────────────────────────────────────────

def fetch_app_owners(object_id: str, tenant_id: str) -> str:
    """
    Fetches owners of an App Registration using its object ID, scoped to
    the SPECIFIC tenant this app lives in.
    Returns a single comma-separated string of display names — both User
    owners and Service Principal/Managed Identity owners are represented
    by their display name (e.g. "Vijay Anand, Subash Kumar, azure-secretgovernance-cross-tenant").

    OWNERSHIP MATCHING: decision_engine.py and runbook_rotation.py match
    ownership by NAME now (not email) — OWNER-EMAILS in Key Vault should
    be configured with display names, e.g. "Vijay Anand, Subash Kumar",
    and the substring match (`if name in app_owners`) works the same way
    it always did, just against names instead of emails.
    """
    url = f"https://graph.microsoft.com/v1.0/applications/{object_id}/owners"
    try:
        b      = _get(url, _auth_hdrs_for_tenant(tenant_id), timeout=15)
        owners = b.get("value", [])

        names: list[str] = []

        for owner in owners:
            odata_type = owner.get("@odata.type", "").lower()

            if "user" in odata_type:
                name  = owner.get("displayName", "")
                email = owner.get("userPrincipalName") or owner.get("mail")
                if name:
                    names.append(name)
                elif email:
                    # No display name on record — email is still a usable
                    # identifier, better than leaving this owner out entirely.
                    names.append(email)
                else:
                    fallback = owner.get("id", "unknown")
                    log.warning(
                        "User owner on app object_id=%s has no displayName/email — id=%r. "
                        "Flagging as NoName so it's visible, not silently dropped.",
                        object_id, fallback,
                    )
                    names.append(f"NoName:{fallback}")

            elif "serviceprincipal" in odata_type:
                # Service Principal / Managed Identity — no email concept,
                # displayName is the correct and only identifier.
                name = owner.get("displayName", "")
                if name:
                    names.append(name)

            else:
                # @odata.type missing/unrecognised — try name, fall back
                # to email if that's all that's available.
                name  = owner.get("displayName", "")
                email = owner.get("userPrincipalName") or owner.get("mail", "")
                if name:
                    names.append(name)
                elif email:
                    names.append(email)

        return ", ".join(names)

    except Exception as e:
        log.warning("fetch_app_owners failed for object_id %s (tenant %s): %s", object_id, tenant_id, e)
        return ""

# ─────────────────────────────────────────────────────────────────────────────
# STEP 2 (parallel) — Fetch owners for ALL apps concurrently
# ─────────────────────────────────────────────────────────────────────────────

def fetch_all_owners_parallel(applications: list[dict]) -> dict[str, str]:
    """
    Fetches owners for all apps in parallel using a thread pool.
    Returns a dict mapping object_id → owners_string (display names only).

    Each app dict must have '_sourceTenantId' set (added by
    fetch_all_applications_all_tenants) so the correct per-tenant
    credential is used — an app's owners must be looked up in the SAME
    tenant the app itself lives in, not necessarily the home tenant.
    """
    results: dict[str, str] = {}

    def _fetch(app: dict) -> tuple[str, str]:
        object_id = app.get("id", "")
        tenant_id = app.get("_sourceTenantId", "")
        if not object_id or not tenant_id:
            return object_id, ""
        names = fetch_app_owners(object_id, tenant_id)
        return object_id, names

    log.info("Fetching owners for %d apps in parallel (%d workers)...",
             len(applications), OWNER_FETCH_WORKERS)
    t0 = time.time()

    with ThreadPoolExecutor(max_workers=OWNER_FETCH_WORKERS) as pool:
        futures = {pool.submit(_fetch, app): app for app in applications}
        for future in as_completed(futures):
            try:
                object_id, names = future.result()
                results[object_id] = names
            except Exception as e:
                app = futures[future]
                log.warning("Owner fetch failed for %s: %s",
                            app.get("displayName", "?"), e)
                results[app.get("id", "")] = ""

    elapsed = time.time() - t0
    log.info("Owner fetch complete — %.1fs for %d apps", elapsed, len(applications))
    return results

def purge_all_sp_rows(list_id: str, list_label: str) -> tuple[int, list[str]]:
    """
    NEW in v10 — deletes EVERY row currently in the given list. Used for
    backup rotation: immediately before writing this run's fresh backup
    snapshot, all rows from the PREVIOUS run's backup are wiped, so only
    the latest run's snapshot ever exists (bounded list size, at the cost
    of deeper backup history — see v10 changelog point 5).

    Reads item IDs directly (no $expand=fields needed — we only need IDs
    to delete) and issues DELETE via Graph $batch, same batching/retry
    infrastructure as every other SharePoint write in this runbook.

    Returns: (deleted_count, errors)
    """
    if not list_id:
        return 0, []

    url = (
        f"https://graph.microsoft.com/v1.0/sites/{SHAREPOINT_SITE_ID}"
        f"/lists/{list_id}/items?$select=id&$top=500"
    )
    item_ids: list[str] = []
    while url:
        b = _get(url, _sp_auth_hdrs(), timeout=30)
        for item in b.get("value", []):
            iid = item.get("id", "")
            if iid:
                item_ids.append(iid)
        url = b.get("@odata.nextLink")

    if not item_ids:
        log.info("%s backup list already empty — nothing to purge.", list_label)
        return 0, []

    log.info("Purging %d prior-run row(s) from %s before writing new backup...",
              len(item_ids), list_label)

    base_url = f"/sites/{SHAREPOINT_SITE_ID}/lists/{list_id}/items"
    deleted  = 0
    errors: list[str] = []

    for chunk_start in range(0, len(item_ids), SP_BATCH_SIZE):
        chunk = item_ids[chunk_start: chunk_start + SP_BATCH_SIZE]
        batch_requests = [
            {
                "id":     str(i),
                "method": "DELETE",
                "url":    f"{base_url}/{iid}",
            }
            for i, iid in enumerate(chunk)
        ]
        try:
            responses = _execute_sp_batch(batch_requests)
            for resp in responses:
                status = resp.get("status", 0)
                if status in (200, 204, 404):
                    # 404 = already gone — treat as successfully absent,
                    # not an error, since the end goal (row not present)
                    # is already satisfied.
                    deleted += 1
                else:
                    errors.append(
                        f"Purge DELETE failed [{status}] for item in {list_label}: "
                        f"{str(resp.get('body', ''))[:150]}"
                    )
        except Exception as e:
            errors.append(f"Purge batch chunk failed for {list_label}: {e}")

        if chunk_start + SP_BATCH_SIZE < len(item_ids):
            time.sleep(SP_BATCH_PAUSE)

    log.info("Purged %d/%d rows from %s.", deleted, len(item_ids), list_label)
    return deleted, errors

def purge_stale_backup_rows(list_id: str, list_label: str, current_run_date: str) -> tuple[int, list[str]]:
    """
    NEW — write-then-purge safe version of backup rotation. Unlike
    purge_all_sp_rows (which deletes EVERY row unconditionally, used by the
    standalone cleanup_sharepoint*.py scripts for a genuine full reset),
    this ONLY deletes rows whose BackupRunDate is NOT current_run_date —
    i.e. rows from a PRIOR run's backup, never this run's own freshly
    written rows.

    This is what makes write-then-purge actually safe: this run's backup
    is written FIRST (see run_discovery's Step 3c), so by the time this
    function runs, today's rows already exist and are protected by the
    BackupRunDate filter — even if this purge fails or the process dies
    immediately after, there is always at least one complete backup
    snapshot present, never a window with zero.

    Needs $expand=fields (not just $select=id like purge_all_sp_rows) since
    the decision of what to delete depends on each row's BackupRunDate
    value, not just its existence.

    Returns: (deleted_count, errors)
    """
    if not list_id:
        return 0, []

    url = (
        f"https://graph.microsoft.com/v1.0/sites/{SHAREPOINT_SITE_ID}"
        f"/lists/{list_id}/items?$expand=fields&$select=id,fields&$top=500"
    )
    stale_item_ids: list[str] = []
    while url:
        b = _get(url, _sp_auth_hdrs(), timeout=30)
        for item in b.get("value", []):
            iid = item.get("id", "")
            run_date = item.get("fields", {}).get("BackupRunDate", "")
            if iid and run_date != current_run_date:
                stale_item_ids.append(iid)
        url = b.get("@odata.nextLink")

    if not stale_item_ids:
        log.info("%s — no stale rows from a prior run to purge (either empty, or "
                 "everything present is already tagged with today's run).", list_label)
        return 0, []

    log.info("Purging %d stale row(s) (prior run's BackupRunDate) from %s — "
             "this run's own fresh rows are excluded and untouched...",
              len(stale_item_ids), list_label)

    base_url = f"/sites/{SHAREPOINT_SITE_ID}/lists/{list_id}/items"
    deleted  = 0
    errors: list[str] = []

    for chunk_start in range(0, len(stale_item_ids), SP_BATCH_SIZE):
        chunk = stale_item_ids[chunk_start: chunk_start + SP_BATCH_SIZE]
        batch_requests = [
            {
                "id":     str(i),
                "method": "DELETE",
                "url":    f"{base_url}/{iid}",
            }
            for i, iid in enumerate(chunk)
        ]
        try:
            responses = _execute_sp_batch(batch_requests)
            for resp in responses:
                status = resp.get("status", 0)
                if status in (200, 204, 404):
                    deleted += 1
                else:
                    errors.append(
                        f"Stale-backup purge DELETE failed [{status}] for item in "
                        f"{list_label}: {str(resp.get('body', ''))[:150]}"
                    )
        except Exception as e:
            errors.append(f"Stale-backup purge batch chunk failed for {list_label}: {e}")

        if chunk_start + SP_BATCH_SIZE < len(stale_item_ids):
            time.sleep(SP_BATCH_PAUSE)

    log.info("Purged %d/%d stale rows from %s.", deleted, len(stale_item_ids), list_label)
    return deleted, errors

# ─────────────────────────────────────────────────────────────────────────────
# STEP 3b — Build backup write operations from the CURRENT (pre-run) state
#          Every field from every current row is copied as-is into a NEW
#          row in SecretAlertRegistryBackup — full snapshot, append-only,
#          never overwritten. Runs BEFORE any of this run's changes are made.
# ─────────────────────────────────────────────────────────────────────────────

# ALLOWLIST — exactly the real data columns confirmed present on the
# SecretAlertRegistryBackup list schema (verified against Graph's actual
# column listing for that list). Using an allowlist instead of a blocklist
# is deliberate: SharePoint's $expand=fields response includes an unknown
# number of internal, read-only system metadata fields (_ComplianceFlags,
# _ColorTag, ComplianceAssetId, and others we haven't necessarily seen yet)
# that vary by tenant/list configuration and are NOT safe to guess a
# complete blocklist for. An allowlist can never accidentally include a
# field we don't know about — worst case it silently omits a real field,
# which is a much safer failure mode than a 403/400 breaking the entire
# backup batch.
_BACKUP_FIELD_ALLOWLIST = {
    "Title", "AppName", "SecretID", "SecretDescription", "ExpirationDate",
    "AlertStatus", "LastChecked", "AlertSentDate", "RotationDetectedDate",
    "JiraTicketKey", "ExpiryNotice", "NewSecretKeyId", "NewSecretVaultName",
    "TenantID", "JiraTicketCreatedDate", "AlertHistory",
    "ExpiryBucket", "AppOwners", "ObjectID", "ManualAppOwners",
    "TeamName", "ProductName", "ProductTeamkeyVaultName",
}

# NEW in v10 — separate allowlist for IgnoredSecretRegistry's own schema
# (DaysExpired/LoggedDate/IgnoreReason instead of the active-list columns
# like AlertStatus/ExpiryBucket, which don't exist on Ignored rows).
_IGNORED_BACKUP_FIELD_ALLOWLIST = {
    "Title", "AppName", "SecretID", "SecretDescription", "ExpirationDate",
    "DaysExpired", "TenantID", "LoggedDate", "IgnoreReason",
}

def build_backup_write_ops(raw_items: list[dict], backup_run_date: str,
                            field_allowlist: set[str] = _BACKUP_FIELD_ALLOWLIST) -> list[dict]:
    """
    Builds Graph $batch write operations to snapshot every current row in
    a source list into its corresponding backup list, tagged with the
    date of this discovery run. Always creates NEW rows (item_id=None) —
    each run's backup is a full snapshot appended fresh (older backup rows
    are deleted separately — see purge_all_sp_rows — so in practice only
    one run's snapshot ever exists at a time; see v10 backup rotation).

    Generic over field_allowlist so the same function backs up both
    SecretAlertRegistry (_BACKUP_FIELD_ALLOWLIST) and IgnoredSecretRegistry
    (_IGNORED_BACKUP_FIELD_ALLOWLIST) — see comment above for why an
    allowlist is used instead of trying to blocklist every possible
    SharePoint-managed system field.
    """
    backup_ops: list[dict] = []
    for item in raw_items:
        f = item.get("fields", {})
        original_item_id = item.get("id", "")

        backup_fields = {
            k: v for k, v in f.items()
            if k in field_allowlist
        }
        backup_fields["OriginalItemId"] = original_item_id
        backup_fields["BackupRunDate"] = backup_run_date

        label = f"{f.get('AppName', 'Unknown')}/{f.get('SecretDescription', '')}"
        backup_ops.append({
            "item_id": None,
            "label":   f"BACKUP:{label}",
            "fields":  backup_fields,
        })

    return backup_ops

# ─────────────────────────────────────────────────────────────────────────────
# STEP 4 — Graph $batch writer (generic — takes target list ID as a param)
#          Bundles up to SP_BATCH_SIZE (20) SharePoint writes per HTTP call.
#          Graph $batch spec: https://learn.microsoft.com/graph/json-batching
# ─────────────────────────────────────────────────────────────────────────────

def _execute_sp_batch(requests: list[dict]) -> list[dict]:
    """
    Sends a single Graph $batch request containing up to 20 SP operations.
    Each request dict has: id, method, url, body (optional).
    Returns list of response dicts from Graph batch response.

    ALWAYS uses _sp_auth_hdrs() (home tenant) — every SharePoint write in
    this runbook (SecretAlertRegistry, IgnoredSecretRegistry,
    SecretAlertRegistryBackup) funnels through this one function, so this
    is the single most important place to get the token scope right.
    """
    batch_body = {"requests": requests}
    hdrs = {
        **_sp_auth_hdrs(),
        "Content-Type": "application/json",
    }
    resp = _post_retry(
        "https://graph.microsoft.com/v1.0/$batch",
        hdrs,
        batch_body,
        timeout=60,
    )
    return resp.get("responses", [])


def batch_write_sp_rows(write_ops: list[dict], list_id: str) -> tuple[int, int, list[str]]:
    """
    Executes SharePoint write operations (create/update) against the given
    list_id using Graph $batch. Generic over target list so it can be reused
    for both SecretAlertRegistry and IgnoredSecretRegistry.

    write_ops: list of dicts with keys:
      - item_id    : str | None  (None → POST new row, str → PATCH existing)
      - fields     : dict        (SharePoint column values)
      - label      : str         (for error messages)

    Returns: (created_count, updated_count, errors)
    """
    base_url = f"/sites/{SHAREPOINT_SITE_ID}/lists/{list_id}/items"

    batch_requests: list[dict] = []
    op_map: dict[str, dict] = {}

    for i, op in enumerate(write_ops):
        req_id  = str(i)
        item_id = op.get("item_id")
        fields  = op.get("fields", {})

        if item_id is None:
            batch_req = {
                "id":      req_id,
                "method":  "POST",
                "url":     base_url,
                "headers": {"Content-Type": "application/json"},
                "body":    {"fields": fields},
            }
        else:
            batch_req = {
                "id":      req_id,
                "method":  "PATCH",
                "url":     f"{base_url}/{item_id}",
                "headers": {"Content-Type": "application/json"},
                "body":    {"fields": fields},
            }

        batch_requests.append(batch_req)
        op_map[req_id] = op

    created = 0
    updated = 0
    errors: list[str] = []

    for chunk_start in range(0, len(batch_requests), SP_BATCH_SIZE):
        chunk = batch_requests[chunk_start: chunk_start + SP_BATCH_SIZE]

        try:
            responses = _execute_sp_batch(chunk)
        except Exception as e:
            for req in chunk:
                label = op_map[req["id"]].get("label", req["id"])
                errors.append(f"Batch chunk failed for {label}: {e}")
            if chunk_start + SP_BATCH_SIZE < len(batch_requests):
                time.sleep(SP_BATCH_PAUSE)
            continue

        retry_as_post: list[dict] = []

        for resp in responses:
            req_id  = str(resp.get("id", ""))
            status  = resp.get("status", 0)
            op      = op_map.get(req_id, {})
            label   = op.get("label", req_id)

            if status in (200, 201, 204):
                if op.get("item_id") is None:
                    created += 1
                else:
                    updated += 1
            elif status == 404 and op.get("item_id") is not None:
                log.warning("404 on PATCH for %s — item_id %s not found, retrying as POST",
                            label, op.get("item_id"))
                retry_as_post.append(op)
            else:
                body_preview = str(resp.get("body", ""))[:200]
                errors.append(
                    f"SP write failed [{status}] for {label}: {body_preview}"
                )

        for op in retry_as_post:
            label  = op.get("label", "?")
            fields = op.get("fields", {})
            # FIX: this was unconditionally injecting AlertStatus="Discovered"
            # into every retry-as-POST, assuming the target was always
            # SecretAlertRegistry. batch_write_sp_rows is GENERIC over both
            # lists (see docstring above) — IgnoredSecretRegistry has no
            # AlertStatus column at all, so any retry against that list 400'd
            # with "Field 'AlertStatus' is not recognized". This surfaced in
            # production specifically when the SAME run's recovery logic
            # deleted an IgnoredSecretRegistry row (moving it back to an
            # active bucket) WHILE another operation in the same batch was
            # still trying to PATCH that now-deleted row — the PATCH 404s,
            # falls into this retry path, and previously always assumed
            # SecretAlertRegistry's schema regardless of which list_id was
            # actually being written to.
            if list_id == SHAREPOINT_LIST_ID and "AlertStatus" not in fields:
                fields["AlertStatus"] = "Discovered"
            retry_req = [{
                "id":      "retry_0",
                "method":  "POST",
                "url":     base_url,
                "headers": {"Content-Type": "application/json"},
                "body":    {"fields": fields},
            }]
            try:
                retry_responses = _execute_sp_batch(retry_req)
                r_status = retry_responses[0].get("status", 0) if retry_responses else 0
                if r_status in (200, 201, 204):
                    created += 1
                    log.info("Retry POST succeeded for %s", label)
                else:
                    body_preview = str(retry_responses[0].get("body", ""))[:200] if retry_responses else ""
                    errors.append(f"Retry POST failed [{r_status}] for {label}: {body_preview}")
            except Exception as e:
                errors.append(f"Retry POST exception for {label}: {e}")

        if chunk_start + SP_BATCH_SIZE < len(batch_requests):
            time.sleep(SP_BATCH_PAUSE)

    return created, updated, errors

# ─────────────────────────────────────────────────────────────────────────────
# MAIN DISCOVERY LOGIC
# ─────────────────────────────────────────────────────────────────────────────

def run_discovery() -> dict:
    today = _now_est_string()
    now   = datetime.now(timezone.utc)

    summary: dict[str, Any] = {
        "runDate":            today,
        "appsScanned":        0,
        "appsSkippedMalformed": 0,  # apps missing appId/object id — entirely skipped
        "secretsSeenInGraph": 0,    # every secret Graph returned, before any skip
        "secretsSkippedMalformed": 0,  # secrets missing keyId/endDateTime — skipped
        "secretsFound":       0,    # secrets actually classified (should equal
                                    # secretsSeenInGraph - secretsSkippedMalformed)
        "rowsCreated":        0,   # SecretAlertRegistry — new rows
        "rowsUpdated":        0,   # SecretAlertRegistry — updated rows
        "ignoredLogged":      0,   # IgnoredSecretRegistry — rows written (Ignore + P5, v10)
        "ignoredSkippedNoList": 0, # would-be-ignored rows NOT written (list ID missing)
        "p5ToIgnoredList":    0,   # RETIRED v10.2 — P5 no longer routes here, kept at 0 for compatibility
        "recoveredFromIgnored": 0, # NEW v10 — rows deleted from Ignored + recreated as active
        "backupRowsWritten":  0,   # SecretAlertRegistryBackup — pre-run snapshot rows
        "backupSkippedNoList": 0,  # backup skipped entirely — list ID not configured
        "ignoredBackupRowsWritten": 0,  # NEW v10 — IgnoredSecretRegistryBackup rows
        "ignoredBackupSkippedNoList": 0, # NEW v10 — ignored backup skipped, list not configured
        "backupRowsPurged":   0,   # NEW v10 — prior-run backup rows deleted before this run's snapshot
        "ignoredBackupRowsPurged": 0,  # NEW v10 — same, for IgnoredSecretRegistryBackup
        "byBucket":           {b: 0 for b in ["P1","P2","P3","P4","ExpiredManualReview","Ignore"]},
        "errors":             [],
    }

    # ── Step 1: Fetch ALL App Registrations across ALL configured tenants ────
    try:
        applications, tenant_fetch_errors = fetch_all_applications_all_tenants()
        summary["appsScanned"] = len(applications)
        summary["errors"].extend(tenant_fetch_errors)
    except Exception as e:
        summary["errors"].append(f"fetch_all_applications_all_tenants failed: {e}")
        return summary

    if not applications:
        log.info("No applications found across any configured tenant — nothing to do.")
        return summary

    # ── Step 2: Fetch owners in parallel ─────────────────────────────────────
    try:
        owners_by_object_id = fetch_all_owners_parallel(applications)
    except Exception as e:
        log.warning("fetch_all_owners_parallel failed: %s — proceeding with empty owners", e)
        owners_by_object_id = {}

    # ── Step 3: Read existing SharePoint rows (this run's PRE-CHANGE state) ───
    # Reads BOTH lists — SecretAlertRegistry (as before) AND, new in v10,
    # IgnoredSecretRegistry, since recovery detection (v10 point 3) needs to
    # know what's currently sitting in Ignored, and the Ignored backup (v10
    # point 4) needs its pre-change snapshot too.
    try:
        existing_rows, raw_current_items = get_existing_sp_rows()
    except Exception as e:
        summary["errors"].append(f"get_existing_sp_rows failed: {e}")
        return summary

    try:
        existing_ignored_rows, raw_current_ignored_items = get_all_ignored_sp_rows()
    except Exception as e:
        summary["errors"].append(f"get_all_ignored_sp_rows failed: {e}")
        return summary

    # Full-fields lookup by (appId, secretId) — needed to diff against current
    # values when updating, so we only PATCH fields that actually changed.
    existing_fields_by_key: dict[tuple[str, str], dict] = {}
    for item in raw_current_items:
        f = item.get("fields", {})
        key = (f.get("Title", ""), f.get("SecretID", ""))
        if key[0] and key[1]:
            existing_fields_by_key[key] = f

    # ── Step 3b: Backup CURRENT state (BOTH lists) before making any changes ──
    # HARD GATE: backup must succeed for BOTH SecretAlertRegistry AND
    # IgnoredSecretRegistry before ANY master-list changes happen. If either
    # backup list isn't configured, or either backup write fails, this run
    # ABORTS here — it does NOT proceed to update either master list. This
    # is deliberate: the whole point of the backup is to guarantee a restore
    # point exists before every change; silently skipping backup and
    # updating anyway would defeat that guarantee exactly when it's needed
    # most (a bad run).
    if not SHAREPOINT_BACKUP_LIST_ID or not SHAREPOINT_IGNORED_BACKUP_LIST_ID:
        summary["backupSkippedNoList"] = len(raw_current_items)
        summary["ignoredBackupSkippedNoList"] = len(raw_current_ignored_items)
        missing = []
        if not SHAREPOINT_BACKUP_LIST_ID:
            missing.append("SHAREPOINT-BACKUP-LIST-ID")
        if not SHAREPOINT_IGNORED_BACKUP_LIST_ID:
            missing.append("SHAREPOINT-IGNORED-BACKUP-LIST-ID")
        summary["errors"].append(
            f"{', '.join(missing)} not configured — aborting run WITHOUT "
            "updating either master list. Backup of BOTH SecretAlertRegistry "
            "and IgnoredSecretRegistry is a hard prerequisite; configure the "
            "missing Key Vault secret(s) and re-run."
        )
        log.error("ABORTING — %s not set. Existing rows were NOT backed up, "
                  "so master-list updates will NOT proceed.", ', '.join(missing))
        return summary

    # ── Step 3c: Write THIS run's backup FIRST, then purge the PRIOR run's ───
    # rows — NOT the other way around. This was flagged as a risk earlier and
    # is fixed here: the old order (purge-then-write) has a real window,
    # however brief, where a mid-run failure leaves BOTH backup lists with
    # ZERO rows until the next successful run. Write-then-purge means there
    # is always at least one complete backup snapshot on disk — briefly two
    # (this run's + the prior run's) immediately after the write, then back
    # down to one once the purge below completes. A failure between write
    # and purge simply leaves the OLD backup rows sitting alongside the new
    # ones — extra rows, not zero, which is a far safer failure mode.
    try:
        backup_ops = build_backup_write_ops(raw_current_items, today, _BACKUP_FIELD_ALLOWLIST)
        if backup_ops:
            backup_created, _backup_updated, backup_errors = batch_write_sp_rows(
                backup_ops, SHAREPOINT_BACKUP_LIST_ID
            )
            summary["backupRowsWritten"] = backup_created
            if backup_errors:
                # ANY backup write failure aborts the run — a partial/incomplete
                # backup is not a safe foundation for proceeding to update the
                # master list. Better to stop and retry than risk updating rows
                # whose pre-change state didn't actually get captured. Since
                # nothing has been purged yet at this point, the PRIOR run's
                # backup is still fully intact — this abort loses nothing.
                summary["errors"].extend(f"[Backup] {e}" for e in backup_errors)
                summary["errors"].append(
                    f"ABORTING — {len(backup_errors)} backup row(s) failed to write. "
                    f"Master-list updates will NOT proceed this run. The prior run's "
                    f"backup is untouched and still intact."
                )
                log.error("ABORTING — %d/%d backup rows failed. Master-list updates "
                          "will NOT proceed. Prior backup untouched. See errors above.",
                          len(backup_errors), len(backup_ops))
                return summary
            log.info("Backed up %d rows to SecretAlertRegistryBackup (run date %s) — "
                     "proceeding to purge the prior run's backup rows.", backup_created, today)
        else:
            log.info("No existing rows to back up — SecretAlertRegistry was empty. "
                     "Nothing to protect — proceeding directly.")

        ignored_backup_ops = build_backup_write_ops(
            raw_current_ignored_items, today, _IGNORED_BACKUP_FIELD_ALLOWLIST
        )
        if ignored_backup_ops:
            ig_backup_created, _ig_backup_updated, ig_backup_errors = batch_write_sp_rows(
                ignored_backup_ops, SHAREPOINT_IGNORED_BACKUP_LIST_ID
            )
            summary["ignoredBackupRowsWritten"] = ig_backup_created
            if ig_backup_errors:
                summary["errors"].extend(f"[Ignored Backup] {e}" for e in ig_backup_errors)
                summary["errors"].append(
                    f"ABORTING — {len(ig_backup_errors)} IgnoredSecretRegistryBackup "
                    f"row(s) failed to write. Master-list updates will NOT proceed this run. "
                    f"The prior run's backup is untouched and still intact."
                )
                log.error("ABORTING — %d/%d ignored-backup rows failed. Prior backup untouched.",
                          len(ig_backup_errors), len(ignored_backup_ops))
                return summary
            log.info("Backed up %d rows to IgnoredSecretRegistryBackup (run date %s).",
                     ig_backup_created, today)
        else:
            log.info("No existing rows to back up — IgnoredSecretRegistry was empty.")
    except Exception as e:
        summary["errors"].append(
            f"ABORTING — backup write step raised an exception: {e}. "
            f"Master-list updates will NOT proceed this run. The prior run's "
            f"backup is untouched and still intact."
        )
        log.error("ABORTING — backup write step raised an exception, master-list "
                  "updates will NOT proceed. Prior backup untouched: %s", e)
        return summary

    # Now purge ONLY rows from a DIFFERENT (older) BackupRunDate than today's
    # — this run's just-written rows are tagged BackupRunDate=today and must
    # survive the purge. A purge failure here does NOT abort the run — this
    # run's fresh backup already exists and master-list updates are safe to
    # proceed; the only consequence of a purge failure is that OLD backup
    # rows linger an extra run (cosmetic — a bigger list — not a data-loss risk).
    try:
        purged_active, purge_active_errors = purge_stale_backup_rows(
            SHAREPOINT_BACKUP_LIST_ID, "SecretAlertRegistryBackup", today
        )
        summary["backupRowsPurged"] = purged_active
        if purge_active_errors:
            summary["errors"].extend(f"[Backup Purge — non-fatal] {e}" for e in purge_active_errors)
            log.warning("%d purge error(s) on SecretAlertRegistryBackup — this run's fresh "
                       "backup is safe; old rows will be retried next run.",
                       len(purge_active_errors))

        purged_ignored, purge_ignored_errors = purge_stale_backup_rows(
            SHAREPOINT_IGNORED_BACKUP_LIST_ID, "IgnoredSecretRegistryBackup", today
        )
        summary["ignoredBackupRowsPurged"] = purged_ignored
        if purge_ignored_errors:
            summary["errors"].extend(f"[Ignored Backup Purge — non-fatal] {e}" for e in purge_ignored_errors)
            log.warning("%d purge error(s) on IgnoredSecretRegistryBackup — this run's fresh "
                       "backup is safe; old rows will be retried next run.",
                       len(purge_ignored_errors))
    except Exception as e:
        # Non-fatal by design — see comment above. This run's backup already
        # succeeded; a purge exception just means old rows linger.
        summary["errors"].append(f"[Backup Purge — non-fatal] purge step raised an exception: {e}")
        log.warning("Backup purge step raised an exception (non-fatal — fresh backup "
                   "already written this run): %s", e)

    # ── Step 4: Build write operations — active rows AND ignored rows ─────────
    write_ops: list[dict]           = []   # → SecretAlertRegistry
    ignored_write_ops: list[dict]   = []   # → IgnoredSecretRegistry
    ignored_delete_ops: list[dict]  = []   # → IgnoredSecretRegistry (v10 recovery — deletes)
    # Tracks which (appId, secretId) keys we've SEEN this run that also exist
    # in Ignored right now — anything in existing_ignored_rows NOT touched
    # by this loop stays in Ignored untouched (still Ignore or still P5).
    recovered_keys: set[tuple[str, str]] = set()

    for app in applications:
        app_id      = app.get("appId", "")
        app_name    = app.get("displayName", "Unknown")
        object_id   = app.get("id", "")
        secrets     = app.get("passwordCredentials", [])
        source_tenant_id = app.get("_sourceTenantId", GRAPH_TENANT_ID)

        if not app_id or not object_id:
            summary["appsSkippedMalformed"] += 1
            log.warning(
                "Skipping app entirely — missing appId or object id: displayName=%s appId=%r id=%r (had %d secrets)",
                app_name, app_id, object_id, len(secrets),
            )
            continue

        if not secrets:
            # Genuinely no secrets on this app — not an error, just nothing to do.
            continue

        app_owners = owners_by_object_id.get(object_id, "")

        for secret in secrets:
            secret_id   = secret.get("keyId", "")
            secret_desc = secret.get("displayName", "")
            expiry_str  = secret.get("endDateTime", "")

            summary["secretsSeenInGraph"] += 1

            if not secret_id or not expiry_str:
                summary["secretsSkippedMalformed"] += 1
                log.warning(
                    "Skipping secret — missing keyId or endDateTime: app=%s (%s) secret_id=%r "
                    "endDateTime=%r displayName=%r",
                    app_name, app_id, secret_id, expiry_str, secret_desc,
                )
                continue

            # Calculate days remaining
            parse_failed = False
            try:
                expiry_dt = _parse_graph_datetime(expiry_str)
                days = (expiry_dt - now).days
            except Exception as e:
                log.warning(
                    "Failed to parse endDateTime=%r for app=%s (%s) secret=%s: %s",
                    expiry_str, app_name, app_id, secret_id, e,
                )
                days = -9999  # fail SAFE — routes to Ignore, never P5
                parse_failed = True

            summary["secretsFound"] += 1
            bucket = _classify_bucket(days)
            notice = _expiry_notice(days, bucket)

            # Use the already-parsed expiry_dt to format date+time consistently,
            # rather than slicing the raw string (which only gave date-only and
            # was fragile — see _parse_graph_datetime for why raw slicing is
            # unreliable). If parsing failed, show the raw string so it's
            # obviously flagged for review instead of a fake-looking date.
            if parse_failed:
                expiry_date = f"UNPARSEABLE: {expiry_str[:50]}"
            elif expiry_str:
                expiry_date = _format_datetime_est(expiry_dt)
            else:
                expiry_date = ""

            summary["byBucket"][bucket] += 1

            label = f"{app_name}/{secret_desc}"

            row_key = (app_id, secret_id)

            # ── Ignore + P5 buckets → BOTH route to IgnoredSecretRegistry (v10) ──
            # v10.2 CHANGE (one-time requirement): P5 (61+ days, safe) now
            # falls through to the NORMAL active-bucket path below and is
            # written to SecretAlertRegistry, NOT IgnoredSecretRegistry.
            # Only genuinely-expired (8+ days ago) secrets still route to
            # IgnoredSecretRegistry. This is a deliberate one-time-run change
            # — the client wants the full picture (P1 through P5) visible in
            # one place, at least for this run; IgnoredSecretRegistry is now
            # reserved purely for "Ignore" (Expired8Plus).
            if bucket == "Ignore":
                ignore_reason = "Expired8Plus"

                if SHAREPOINT_IGNORED_LIST_ID:
                    already_ignored_id = existing_ignored_rows.get(row_key)
                    ignored_write_ops.append({
                        # If this (appId, secretId) already has a row in
                        # IgnoredSecretRegistry from a prior run, PATCH it
                        # in place instead of appending a duplicate — the
                        # ignored list reflects CURRENT ignore state, not
                        # an append-only log (the backup list is what
                        # preserves history now, per v10 point 4/5).
                        "item_id": already_ignored_id,
                        "label":   label,
                        "fields": {
                            "Title":             app_id,
                            "AppName":           app_name,
                            "SecretID":          secret_id,
                            "SecretDescription": secret_desc,
                            "ExpirationDate":    expiry_date,
                            "DaysExpired":       abs(days) if days != -9999 else None,
                            "TenantID":          source_tenant_id,
                            "LoggedDate":        today,
                            "IgnoreReason":      ignore_reason,
                        },
                    })
                    if already_ignored_id is not None:
                        recovered_keys.add(row_key)  # still ignored — not a recovery, just mark seen
                else:
                    summary["ignoredSkippedNoList"] += 1
                continue

            # ── Active bucket (P1-P4, ExpiredManualReview) ────────────────────
            existing_id = existing_rows.get(row_key)

            # v10 RECOVERY: this secret is classified into an ACTIVE bucket
            # this run, but it currently has a row sitting in
            # IgnoredSecretRegistry (e.g. was P5 or Expired8Plus last run,
            # its endDateTime was extended in Entra, now it's back to P1-P4).
            # Delete the stale Ignored row and fall through to the normal
            # "new row" creation path below — ManualAppOwners is intentionally
            # left blank on this fresh SecretAlertRegistry row, same as any
            # other brand-new secret, per the v10 design decision.
            stale_ignored_id = existing_ignored_rows.get(row_key)
            if stale_ignored_id is not None:
                ignored_delete_ops.append({
                    "item_id": stale_ignored_id,
                    "label":   f"RECOVERED:{label}",
                })
                recovered_keys.add(row_key)
                summary["recoveredFromIgnored"] += 1
                log.info("Recovery — %s moved from IgnoredSecretRegistry back to "
                         "an active bucket (%s). Deleting Ignored row %s, creating "
                         "fresh SecretAlertRegistry row.", label, bucket, stale_ignored_id)
                existing_id = None  # force CREATE, not PATCH — no active row exists yet

            if existing_id is None:
                write_ops.append({
                    "item_id": None,
                    "label":   label,
                    "fields": {
                        "Title":             app_id,
                        "AppName":           app_name,
                        "SecretID":          secret_id,
                        "SecretDescription": secret_desc,
                        "ExpirationDate":    expiry_date,
                        "ExpiryBucket":      bucket,
                        "ExpiryNotice":      notice,
                        "AppOwners":         app_owners,
                        "ObjectID":          object_id,
                        "TenantID":          source_tenant_id,
                        "LastChecked":       today,
                        "AlertStatus":       "Discovered",
                    },
                })
            else:
                # PARTIAL UPDATE — only send fields that actually changed vs
                # the row's current stored values. LastChecked is always
                # included regardless of diffing — it's a heartbeat/"last
                # verified" timestamp, not a value that should be gated on
                # whether anything else changed.
                current = existing_fields_by_key.get(row_key, {})
                # NOTE (v10.1): candidate_fields is the EXHAUSTIVE list of fields
                # discovery ever writes on an update. ManualAppOwners is
                # deliberately absent — it is a manually-maintained column
                # (admin-filled, used by the LangChain/rotation runbooks) and
                # must never be touched by discovery, whether or not Entra's
                # own AppOwners value has changed. Do not add it here.
                # TeamName, ProductName, and ProductTeamkeyVaultName follow
                # the exact same rule — all three are filled in by the team
                # by hand (or copied automatically by monitoring's lineage
                # tracking when a secret rotates), and discovery must never
                # overwrite them either. Do not add any of these three here.
                #
                # TenantID ADDED in v10.1 — a bug in v10 wrote this to
                # Ignore/P5 rows only, never to active-bucket rows on either
                # create or update, leaving TenantID permanently blank on every
                # SecretAlertRegistry row. Included here so existing rows with
                # a blank/stale TenantID get corrected on the next discovery
                # run, not just newly-created ones. (TenantName was removed
                # from this list — the column no longer exists in SharePoint.)
                candidate_fields = {
                    "AppOwners":      app_owners,
                    "ExpiryBucket":   bucket,
                    "ExpiryNotice":   notice,
                    "ExpirationDate": expiry_date,
                    "ObjectID":       object_id,
                    "TenantID":       source_tenant_id,
                }
                changed_fields = {
                    k: v for k, v in candidate_fields.items()
                    if str(current.get(k, "")) != str(v)
                }
                changed_fields["LastChecked"] = today

                if len(changed_fields) > 1:
                    # Something beyond just the heartbeat actually changed —
                    # log what, for a readable audit trail without needing
                    # to diff SharePoint versions manually.
                    real_changes = {k: v for k, v in changed_fields.items() if k != "LastChecked"}
                    log.info("Row changed — %s: %s", label, real_changes)

                write_ops.append({
                    "item_id": existing_id,
                    "label":   label,
                    "fields":  changed_fields,
                })

    log.info("Built %d active write ops + %d ignored write ops + %d ignored delete ops (recovery)",
             len(write_ops), len(ignored_write_ops), len(ignored_delete_ops))

    # ── Step 5: Batch-write active rows to SecretAlertRegistry ────────────────
    if write_ops:
        created, updated, batch_errors = batch_write_sp_rows(write_ops, SHAREPOINT_LIST_ID)
        summary["rowsCreated"] = created
        summary["rowsUpdated"] = updated
        summary["errors"].extend(batch_errors)
    else:
        log.info("No active write operations to execute.")

    # ── Step 6: Batch-write (create-or-update) ignored rows to IgnoredSecretRegistry ─
    # v10: this is now an upsert (existing Ignore/P5 rows are PATCHed in
    # place, not duplicated) — created+updated together equal ignoredLogged.
    if ignored_write_ops:
        ig_created, ig_updated, ig_errors = batch_write_sp_rows(
            ignored_write_ops, SHAREPOINT_IGNORED_LIST_ID
        )
        summary["ignoredLogged"] = ig_created + ig_updated
        summary["errors"].extend(f"[IgnoredSecretRegistry] {e}" for e in ig_errors)
    else:
        log.info("No ignored write operations to execute.")

    # ── Step 6b: Delete RECOVERED rows from IgnoredSecretRegistry (v10) ──────
    # These are secrets that were sitting in Ignored (Expired8Plus — P5 no
    # Expired8Plus) but reclassified this run into an active bucket — their
    # fresh SecretAlertRegistry row was already created in Step 5 above, so
    # the stale Ignored row is now redundant and must be removed so the two
    # lists don't both claim the same secret.
    if ignored_delete_ops and SHAREPOINT_IGNORED_LIST_ID:
        base_url = f"/sites/{SHAREPOINT_SITE_ID}/lists/{SHAREPOINT_IGNORED_LIST_ID}/items"
        for chunk_start in range(0, len(ignored_delete_ops), SP_BATCH_SIZE):
            chunk = ignored_delete_ops[chunk_start: chunk_start + SP_BATCH_SIZE]
            batch_requests = [
                {"id": str(i), "method": "DELETE", "url": f"{base_url}/{op['item_id']}"}
                for i, op in enumerate(chunk)
            ]
            try:
                responses = _execute_sp_batch(batch_requests)
                for resp in responses:
                    status = resp.get("status", 0)
                    if status not in (200, 204, 404):
                        req_id = str(resp.get("id", ""))
                        idx = int(req_id) if req_id.isdigit() else -1
                        label = chunk[idx].get("label", req_id) if 0 <= idx < len(chunk) else req_id
                        summary["errors"].append(
                            f"[Recovery Delete] Failed to delete stale Ignored row for "
                            f"{label} [{status}]: {str(resp.get('body', ''))[:150]}"
                        )
            except Exception as e:
                summary["errors"].append(f"[Recovery Delete] Batch chunk failed: {e}")

            if chunk_start + SP_BATCH_SIZE < len(ignored_delete_ops):
                time.sleep(SP_BATCH_PAUSE)

        log.info("Deleted %d recovered row(s) from IgnoredSecretRegistry.", len(ignored_delete_ops))

    return summary
