# Sync field edits after In Progress

**Rule ID:** 4062245 &middot; **UUID:** `019ff98b-e8ee-7397-bf73-8de5c4417f25` &middot; **State:** Enabled

**Trigger:** `jira.issue.field.changed`, `ANY_CHANGE`, on 9 named custom fields: `TeamName`,
`ProductName`, `ProductTeamsKeyVaultName`, `NewSecretKeyId`, `NewSecretUpdatedReferenceInventory`,
`NewSecretName`, `NewSecretUpdatedReferenceInventoryPresent`, `NewSecretPresent`,
`NewSecretKeyIDPresent`.

**What it does:** one rule, two branches, both reacting to the same field-edit trigger:

- **If `Status == Resolved`:** for each of the 9 watched fields, if the changelog shows that
  specific field just changed, reverts it back to its pre-edit value
  (`{{changelog.<Field>.fromString}}`) and posts a private comment: *"This field is locked while
  the ticket is Resolved. Move the status to In Progress or To Do to make changes."* Effectively
  makes all 9 fields read-only once Resolved.
- **If `Status != Resolved`:** fires an outgoing webhook to Container 1's `/jira-status-update`
  proxy with `"overwrite": true`, forcing Container 2 to write the field unconditionally rather
  than only backfilling a blank column &mdash; an explicit client requirement, since an engineer
  correcting a field after the fact needs to see that correction take effect immediately.

See the [Jira Automation](/azure-secret-governance/jira#keeping-field-edits-in-sync-after-in-progress)
page for the full write-up of this rule's role in the system.

<Callout type="info">
  **Fixed since the first review of this rule (2026-08-18):** the block guarding `NewSecretName`
  (customfield_10189, synced into SharePoint's `NewSecretVaultName` column) used to reference
  `{{changelog.NewSecretVaultName...}}` &mdash; a field name that doesn't exist in Jira (the real
  name is `NewSecretName`), so that block silently never fired. Now corrected to reference
  `NewSecretName` consistently. Separately, `NewSecretKeyIDPresent` was in the trigger's watch
  list from the start but had no matching lock block at all; one has since been added (the
  9th block below).
</Callout>
