# GitHub Actions — the big picture

A built-in automation engine inside every GitHub repo. No third-party tools, no separate setup — just YAML files in your codebase.

---

## What is it, really?

Think of GitHub Actions like a personal assistant sitting inside your GitHub repo.

Every time something happens — you push code, open a PR, merge a branch — GitHub Actions wakes up and asks: *"Is there a workflow for this?"* If yes, it runs it automatically.

No manual steps. No forgetting to run tests. No "it works on my machine" deploys.

---

## The three things it does well

**Automates the boring stuff**

Stop manually running tests, building code, or deploying apps. Actions handles all of it for you whenever you push or open a PR.

**Lives inside GitHub**

Workflows are YAML files in your repo — version controlled, visible to your team, and no third-party CI dashboard to manage. Same repo, same PR process, same access controls.

**10,000+ prebuilt actions**

The GitHub Marketplace has ready-made actions for almost everything — checkout, deploy, notify Slack, run tests, and more. Before writing custom scripts, always check there first.

> Think of it like: every time something happens in your repo (a push, a PR, a schedule) — GitHub Actions can automatically respond and run tasks for you.

---

## How does it compare to Jenkins or CircleCI?

GitHub Actions lives inside your repo. No separate server to manage, no third-party login to hand out. If someone can read the repo, they can read the workflows.

Jenkins is powerful but needs a dedicated server and a lot of config overhead. CircleCI is good but it's another tool with another dashboard. For a team already on GitHub, Actions is the obvious choice.

## Read this before anything else

**The `needs` keyword is everything.** Without it, all your jobs run at the same time. A failed test won't stop a deploy. Always chain your jobs explicitly.

**Pin your action versions.** Use `@v4` not `@latest`. If someone releases a breaking update, your workflow breaks silently on the next run.

**YAML indentation is your biggest enemy.** Two spaces per level. No tabs. Ever. The GitHub editor highlights errors in real time — use it.
