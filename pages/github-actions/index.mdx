# GitHub Actions — the big picture

## Read this first

A few things the course glosses over too quickly:

**The `needs` keyword is the most important concept in CI/CD pipelines.** Without it, all your jobs run in parallel — a failed test won't stop a deploy. Always chain your jobs explicitly.

**Pin your action versions** (`@v4` not just `@latest`). If a marketplace action releases a breaking change and you're unpinned, your workflow silently breaks.

**YAML indentation errors are the #1 beginner mistake.** Use a linter or the GitHub editor, which highlights formatting issues in real time.

## How does it compare to Jenkins or CircleCI?

GitHub Actions lives inside your repo — the workflow files are version controlled alongside your code. No separate CI server to manage, no credentials to a third-party dashboard to hand out. If someone can see the repo, they can see the workflows.

Jenkins is more powerful for complex enterprise setups but requires a dedicated server and a lot of configuration overhead. CircleCI is good but it's another tool with another login. For a team already on GitHub, Actions is the obvious default.
